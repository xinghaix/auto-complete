# 性能说明

[English](PERFORMANCE.en.md) · [文档目录](README.md)

行内补全在**打字热路径**上。优先顺序是：

1. 不打断编辑  
2. 尽快丢掉无用请求  
3. 绝不让旧结果盖住新光标位置  

而不是无限加大上下文、死等模型。

## 默认预算（实现默认值，不是 SLA）

| 项目 | 默认 |
|---|---:|
| 防抖 最短 / 起始 / 最长 | 150 / 300 / 1000 ms |
| 补全超时 | 3000 ms（500–30000） |
| 设置页探测超时 | 15000 ms |
| 输出 tokens | 128（16–1024） |
| 前缀 / 后缀字符 | 8000 / 2000 |
| 最大文件 | 512 KB |
| 同时在途请求 | 1 |
| 建议缓存 / prompt LRU | 20 / 64 |
| 内存日志条数 | 1000 |
| 最近文件 | 关（开时约 3×1200 字） |

模型慢、代理慢、服务排队，都不在插件控制范围内。

## 请求前会拦什么

按顺序大致是：总开关 → 自动触发/snooze → 语言禁用 → 注释/字符串 → 文件太大 → ignore → 配置无效 → 缓存命中 → 上下文 skip → 错误退避。

能拦则不发网。手动触发可跳过自动防抖，但仍过安全相关检查。

## 取消与并发

- 同一文件新请求会取消旧请求  
- 过期 generation 的结果直接丢  
- 达到并发上限时取消别的文件上的在途请求，不无限排队  
- 因继续输入而取消是**正常路径**，默认不弹错  

## 上下文与缓存

只保留离光标最近的前后文。路径默认可发；最近文件默认关。有两级本地缓存，命中后仍会过滤重复文本。

## 错误退避

| 类型 | 例子 | 行为 |
|---|---|---|
| 取消 | 继续输入 | 静默 |
| 严重 | 401/403 | 停一段时间，可通知 |
| 可重试 | 429、5xx、超时 | 退避后允许再试 |
| 空结果 | 2xx 无文本 | 不显示建议 |

改 endpoint 后先用连接探测，别让热路径反复撞错配置。

## 怎么自己查

看日志里的耗时、状态码、是否缓存命中、是否被 cancel。连续输入时不应有旧建议闪回；超大文件和 ignore 路径不应出网。

相关测试在 `engine-jvm`、`plugin`、`engine-ts`、`settings-ui` 测试目录。
